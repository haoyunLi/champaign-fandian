# 饭点 · 香槟今天吃什么

适合发到微信群的中文餐馆投票与带饭登记网页。

- 所有人共用餐馆库，可添加、删除和修改名称、类型、地址。删除前需确认，删除后可撤销；已开始的投票及带饭记录不受影响。
- 每位发起人独立勾选本轮候选；开始后名单固定。
- 首页置顶当前浏览器发起、参与或保存的进行中饭局，直接继续投票或查看带饭；已从个人历史移除的参与记录不再展示。
- 「历史记录」包括当前浏览器发起、参与或主动保存的投票，支持全部、我发起的、我参与的、回收站分类和分页。投票、登记带饭或认领后自动保存；取消登记或退回认领后仍保留历史。已存在的投票、带饭登记和当前认领关系会自动补入历史。
- 参与者可从自己的历史中移除记录并恢复，不影响原投票或其他人。发起人删除整轮投票后，原链接及参与者的对应记录暂时不可访问；仅发起人可恢复整轮。个人移除的记录不会被自动参与记录重新加回。
- 发起时选择「自主投票」或「随机抽签」，创建后玩法固定。自主投票由群友选择一家候选餐馆；随机抽签由服务器等概率抽取餐馆并自动计一票。两种模式提交后均不可改票，按最高票决定餐馆。
- 以前创建的投票继续使用随机抽签；历史记录显示每轮玩法。
- 历史记录支持「再来一局」，沿用上一轮候选快照和玩法，创建没有旧投票、带饭或截止时间的新饭局；重复提交不会重复创建。成功投票、登记和认领后记住常用昵称，在同一浏览器中自动填入。
- 同一浏览器每轮一票，同一昵称每轮不可重复。没有接入微信身份认证；更换浏览器或清除 Cookie 会被视为新的访客，也会失去原来的发起人权限。
- 任何持有本轮链接的人都可以确认结束投票，无需是发起人或已投票。确认时显示当前投票人数，至少收到一票后才能结束；最高票获胜，平票在并列餐馆中随机选一家。结果和带饭截止时间由首次确认固定，重复确认不会更改。
- 投票时突出候选餐馆；餐馆确定后优先展示选定餐馆和带饭清单，完整票数默认折叠。手机页面底部保留当前阶段的主要操作入口。
- 餐馆确定后进入「带饭中」，可以登记菜名、份数和备注，朋友认领并标记「已带回」。至少一条登记且全部已带回时结束；否则从确定餐馆起满 12 小时自动结束，没有登记也等待满 12 小时。未认领的登记可由本人编辑或取消；编辑不重置截止时间，也不会结束饭局。
- 带饭清单支持全部、待认领、我来带、我的登记筛选，并可复制本人携带的菜名、数量、备注和收餐人。认领和编辑会核对最新内容，避免认领到刚被修改的旧菜名。
- 标记最后一份已带回前，明确确认本轮将结束、不能继续加单；多人同时带回也必须经过最后一份确认。取消登记前提示可能结束本轮。
- 饭局结束后带饭清单只读，未完成登记不会自动标记为已带回。截止时间由服务器执行，关闭页面或删除后恢复不会重置。旧版没有确认时间的已确定饭局使用 2026-09-12 06:42:54 UTC 起的固定 12 小时兼容窗口；旧清单已全部带回的直接结束。
- 投票、餐馆和带饭记录保存在共享 D1 数据库。浏览器 Cookie 仅用于识别访客，不保存投票或带饭记录。

默认餐馆：Culver’s、Raising Cane’s、上海菜（店名可补全）、Chick-fil-A、Kung Fu BBQ（盒饭）、Chipotle。没有 Panda Express。

## 本地运行

需要 Node.js 22.13 或更新版本。`npm run install:ci` 安装依赖；`npm run build` 生成 Cloudflare Worker。按 `drizzle/` 中的顺序将迁移应用到本地 D1，然后 `npm run start` 预览。

数据库结构位于 `db/schema.ts`，所有 API 使用预处理语句。投票唯一约束、结束投票及认领更新在数据库中保证原子性。订单提交采用请求 ID 去重。房间状态有递增版本，前端拒绝过期响应。

已用本地测试数据验证共享编辑、投票池快照、22 人投票、并发重复投票、昵称去重、发起人权限、固定赢家、结束后拒票、带饭登记重试去重、同时认领与带回权限。另完成手机界面流程检查。历史功能已验证同时间分页、身份隔离、删除后七类操作拒绝、进行中和已结束投票恢复、完整保留带饭认领状态，以及删除与投票并发。

两种玩法已验证旧记录升级、默认随机兼容、自主投票准确计票、无效或跨轮候选拒绝、重复与并发投票保护、最高票与平票结果固定，以及历史恢复和带饭流程。

参与历史已验证旧记录补入、相同时间分页、参与者与发起人分类、个人移除与恢复、主持人删除权限、未参与者隔离、失败投票/认领不收录，以及取消登记和主持人退回旧认领后仍保留记录。

六项体验改进已通过独立本地数据库的 112 次 API 请求验证，覆盖进行中筛选与分页、带饭编辑与认领并发、最后一份带回确认、截止后拒绝修改、昵称保存和重复重开去重。另完成 320/375 像素手机界面的投票、确认餐馆、编辑、认领、复制、带回和历史重开流程检查。

带饭功能仅用于群内协调，不会向餐馆下单、扣费或发送微信消息。拥有本轮链接的人可以查看群昵称、投票和带饭备注。
